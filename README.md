## What We Have Proven (With Receipts)

These are claims substantiated by operational evidence — not theoretical, not aspirational.

### 1. Tripartite Quorum — 3-node mesh operates
Three physical nodes (swarm1, swarm2, kyle-node-1) running Transportarr v2.2 P2P. Three ISOs transferred cross-node with SHA256 verification. 24 concurrent health endpoints respond in under 320ms. 22 services operating on bare-metal Debian and EndeavourOS.

### 2. Sovereign Ledger — provenance in production
169 Notarr receipt entries. Zero malformed. Zero unsafe. 55 scene releases each with cryptographic SHA256SUMS + SFV + NFO. Structured issue tracking via Loggarr. Append-only, durable, auditable.

### 3. Resilience — survival of node death
AMD MI300X (192GB VRAM, "giant1") deprovisioned May 14, 2026. System reorganized across two small Debian nodes. 47,792 files classified across 96 parallel lanes. 8 stalled arrs autonomously recovered. Transportarr v2.2 supports resume on partial transfers.

### 4. Sovereign voice — zero cloud TTS
Piper TTS (120MB ONNX model, FOSS, MIT license) deployed on Actarr v3. All 11 teaser lines generated locally. No cloud dependency for text-to-speech.

### 5. Self-hosted search — zero tracking
SearXNG running on local infrastructure. Seven search engines. Zero telemetry. No third-party logging of research queries.

### 6. Internal event bus — 149K events/sec
Ergo IRCd + mIRCarr bridge processing 149,000 events per second across 5 channels. 30 action types blocked by safety filter. Passive-observer mode confirmed. 164 observations from 500-lane bus test.

## Development Methodology — Honest Disclosure

**The papers were compiled using an AMD MI300X (192GB VRAM) running locally in Thunder Bay.** Research was conducted by 60 subagents querying academic databases (arXiv, Semantic Scholar, IEEE, ACM).

**Development and testing of the Dreamarr stack — including the arrs that execute the concepts described in these papers — used cloud-based large language models:**

- **DeepSeek v4 Pro** (extensively via Ollama Cloud — primary development model)
- OpenAI (GPT-4o, GPT-4 Turbo via ChatGPT Pro OAuth)
- Anthropic (Claude Sonnet via OpenCode)
- Google (Gemini via web interface)
- Moonshot AI (Kimi K2.6 via OpenCode)

These models assisted with code generation, architecture design, standards drafting, and cross-platform verification. The papers describe a sovereign future; the tools that built the software were a mix of sovereign and cloud. We believe this is honest, and we believe it makes the work stronger — we used every resource available, and when we could run sovereign, we did.

**Our goal is full sovereignty.** We are not there yet. These papers articulate the destination. The operational stack is the path.

## Review Process

**Each paper underwent internal review by a multi-model consortium:**

- DeepSeek v4 Pro via Ollama Cloud (primary review: code alignment, technical accuracy, structure)
- Anthropic Claude (secondary review: argument coherence, citation quality)
- Google Gemini (tertiary review: factual verification, cross-referencing)
- Moonshot Kimi (quaternary review: technical accuracy, edge cases)

**This is not traditional academic peer review.** No external human reviewers. No journal submission. No institutional affiliation. We are transparent about this. The papers represent a novel approach to AI-assisted research: a human architect working with a multi-model consortium to produce interdisciplinary synthesis. We believe the quality speaks for itself, and we invite genuine academic peer review from any qualified researcher who wishes to engage.
